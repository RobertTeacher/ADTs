Examiner-informed Paper 4 Tips

Paraphrased from Cambridge Principal Examiner Reports and aligned to the Unit 19 visualisers.

How to use these: treat each tip as a debugging checklist. The reports repeatedly show that candidates often know the broad algorithm but lose marks through pointer conventions, boundary conditions, return values, data types, or by replacing the requested algorithm with a different one.
Queue

Use the variables the question provides

If NumberItems is supplied, use it for full/empty checks. Store new data at the tail, remove from the head, and wrap circular pointers correctly. Do not increment both pointers during one enqueue.

June 2025 — Paper 41/43 Practical
Stack

Follow the stated TopPointer convention

A full check depends on whether the pointer represents the last occupied position or the next free position. Do not use append() when the task explicitly requires an array and pointer implementation.

June 2025 — Paper 42 Practical
Binary search

Boundary updates must remove the midpoint

Use a condition equivalent to low <= high. When the target is larger, move to mid + 1; when smaller, use mid - 1. A linear search is not a substitute when binary search is requested.

June 2025 — Paper 43 Practical
Sorting

Do not change the requested algorithm

When an incomplete algorithm is provided, preserve its structure and functionality. Examiner reports noted candidates changing the algorithm or reverting to a different sort. Keep paired data together when swapping records.

Linked structures

Follow pointers, not storage order

For linked lists and trees, the physical array order is not the traversal order. Update the correct links, keep track of the previous/current nodes when deleting, and reconnect the structure before reusing a freed node.

June 2025 — Practical comments on linked/tree structures
Binary tree

Respect null pointers and object/method relationships

Tree answers lose marks when nodes are connected to the wrong pointer field, null links are omitted, or a method is called as a standalone function. In recursive tree code, pass the correct child node/reference.

June 2025 — Paper 41 Practical
Recursion

Show both the general case and the base case

A recursive algorithm must call itself, have a terminating base case, and change state toward that base case. When tracing, remember that completed calls return through the suspended calls on the stack.

June 2025 examiner report + O/N 2025 recursion marking guidance
Return values

Nothing runs after a return in that call

Update pointers and counters before returning. If a function returns data needed by the next task, store or use that returned value rather than ignoring it.

June 2025 — Practical reports
Data types

Copy supplied data exactly

The reports highlight errors such as using integer -1 when the question supplied the string "-1". Match the required type and convert pseudocode operators to the syntax of your chosen language.

June 2025 — Paper 42 Practical
Evidence document

Make testing evidence readable

Copy program code as text into the evidence document. Use screenshots for test results, ensure inputs and outputs are fully visible, and keep the evidence legible.
