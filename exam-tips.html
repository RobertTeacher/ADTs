Examiner-informed Paper 4 Tips

Use these as a debugging checklist. Broad algorithm knowledge can still lose marks if pointer meanings, bounds, return values, data types or required evidence are handled incorrectly.

Queue

Use the variables provided

June 2025
Examiner pattern

Head/Tail roles were mixed up, circular wrap-around was missed, or NumberItems was not used consistently.

Before you submit

State what each pointer means, verify full/empty conditions, and test the final index wrapping to 0.

Stack

Follow the TopPointer convention

June 2025
Examiner pattern

Full/empty checks were wrong because candidates assumed a different pointer meaning or used append() instead of the required array-and-pointer method.

Before you submit

Write one sentence: “TopPointer means …”. Make every check and update match it.

Binary search

Remove the midpoint

June 2025
Examiner pattern

Incorrect loop conditions and bounds such as mid instead of mid + 1 / mid - 1 caused non-terminating or incomplete searches.

Before you submit

Check that every iteration makes the search range smaller and an unsuccessful search can terminate.

Sorting

Keep the requested algorithm

June 2023 / 2025
Examiner pattern

Some candidates altered the supplied algorithm or effectively implemented a different sort.

Before you submit

Insertion sort stores a key and shifts. Bubble sort compares adjacent items and swaps. Match the requested method.

Linked structures

Follow pointers, not array order

June 2025
Examiner pattern

Physical array order was treated as logical list order, or deletion changed the wrong pointer.

Before you submit

Trace Current and Previous. Reconnect the active list before returning a node to the free list.

Binary tree

Pass the correct child reference

June 2025
Examiner pattern

Marks were lost through wrong child fields, omitted null links, or incorrect method/function references.

Before you submit

For each recursive call, identify whether you are passing the left child, right child or the null/base case.

Recursion

Base case + progress

2025 reports / marking guidance
Examiner pattern

Recursive solutions failed when they had no terminating base case or the recursive call did not move toward it.

Before you submit

Underline the base case and circle the expression that changes on every recursive call.

Return values

Update first, return last

June 2025
Examiner pattern

Some state changes were placed after return, or a returned value required later was ignored.

Before you submit

Check the final lines of every function: update state, then return; store the returned value when needed.

Data types

Copy supplied data exactly

June 2025
Examiner pattern

Type mismatches occurred when candidates changed supplied representations, including sentinel values.

Before you submit

Check quotes, integer conversion and sentinel values against the question before debugging the algorithm.

Evidence document

Make tests readable

June 2023 / 2025
Examiner pattern

Evidence lost value when code, test input or output could not be read clearly.

Before you submit

Keep code readable and ensure required test input and resulting output are clearly visible.

30-second final check

Names matchFunctions, parameters and variables match the question.
Bounds terminateLoops and recursion move toward a stopping condition.
Pointers are consistentFull, empty, insert and delete logic use one convention.
Return is lastRequired state updates happen before exit.
Algorithm is the requested oneNo shortcut has replaced the required method.
Evidence is readableInputs and outputs can be seen clearly.
